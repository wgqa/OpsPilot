# 验收与效果评测方案

**状态：待评审设计，八案尚未作为一个套件运行。** 将以下旅程作为冻结评测的增补。既有 E01–E10、G1–G8、AR‑04A/B、历史 RED 与分母各自保留。评测者独立保存隐藏标签和期望 Outcome，运行时模型、在线 Verifier 和工具只看可授权的输入。优先复用已有回调、协议、S1/S2 与本地工单夹具。

## 八个验收案例

| 编号、用户旅程 | 设置与扰动 | 必须观察到的结果 | 反向/合法对照、取证 |
|---|---|---|---|
| 1. 四条分散条件，压缩后继续调查 | 用户分四轮要求仅事件 E7、用 v2、查指定时段、分别列 Delivery 与 Receiver；中插协议 B 和闲聊，在 20–40 轮内跨过压缩水位至少两次。隐藏评测表保存每条原意及消息序号。 | 最后“按前面的条件查”解析到 A。实际模型输入能还原四项及出处，结果逐项满足；材料字段值也要匹配，不能只查 marker。仅取 A 绑定的当前观察。 | 同义措辞保持结论；只改可信 Receiver 状态时结论改变。另把 B 专属材料放入同一 Session，断言其正文不进 A；绑定前明确给 A 的合法材料仍可使用。检查摘要代际、实际 messages、Evidence 和答案。 |
| 2. 昨天暂停，今天说“继续” | A 调查止于缺 Receiver 事实或已安全暂停，两进程、同一持久 DB，关闭客户端，受控时钟推进 24h，再登录。分别覆盖重开原 Session、新 Session 回到 A。 | 若唯一授权未完目标为 A，显示其目标、已知/待查和停点；使用原 Task 与当前有效输入，可开新 Run。旧 Evidence 过期先复核；暂停期间无自动调查/新写，用户无需重述条件。 | 在等待审批时说“继续”只能显示审批进展。已 ABORTED/已完成的 A 不得唤醒；同名他人目标不泄露。记录 DB 时间、目标、revision、两侧 Run/Checkpoint 和派发计数。 |
| 3. 两个未完目标，指代不清 | 同 owner 有 A、B 两个目标，可有相同订单和相近标题。让 B 成为最近展示项，再发“继续”；对调 A/B 的时间戳重做。在另一数据集让二目标同属一个 Task。 | 返回只含可见必要信息的区分问题；此时新增调查 Run、业务工具调用和写入均为 0。点选 A 后仅推进 A；若目标在同一 Task，选定其 goal 后再取有效条件。 | 主动选中且明确说“继续查 A 的 Receiver”可直接推进，避免每次都问。选项出现后撤掉 A 权限，提交旧选择须安全失败。取浏览器请求、候选来源、受理命令和状态增量。 |
| 4. 修改和撤回早期条件 | 同一目标先限昨夜并要求列两层状态，后把时段改全天，再撤回输出格式。另测“如果改全天会怎样”及双标签页对同一旧 revision 提交。 | 正式变更后时段=全天，输出格式撤回，其他条件仍有效；高水位与来源可追，旧条件即使存在历史中也不能作为有效输入。影响调查依据时旧 Run/Plan 失效。 | 假设、否定和取消提案不落正式变更；重放同一操作只产生一次效果，冲突提交可刷新重选。检查 messages、工作项和 TaskControl、实际输入、最终查询与答案。 |
| 5. “重新生成” | A 有已交付答案及引用。“把刚才回答改成表格”“重新查当前状态”“重新生成”三种输入，最后一种设置成可能指报告或重查。 | 改写引用原 answer_id 并验证来源，MCP 增量 0；请求重查才允许新只读 Run/当前观察；在有歧义时问清。报告/工单已交付也不得触发第二次 DELIVER/REPAIR。 | 同一网络操作重送复用原 operation_id；两次真正要求改写可得两个答案。若旧引用失效，说明能用的部分并允许用户请求重新调查。检查 answer/run/intent/ledger 对应关系。 |
| 6. Task 材料过期或 Grant 撤销 | 先引用有权限的协议摘录并触发压缩，随后分别在选择后、外发前、checkpoint 续跑前、回答提交前撤销权限或换版本。并设一个仍合法的不同来源。 | 不得新发送受限正文或将其衍生答案提交为有效结论；已发送不可追回，后续提交/再用要拦截。有效来源仍可用。可再取证的 TTL 过期允许在预算内刷新；无权优雅停止且不泄露对象存在性。 | 普通用户曾自己提供的文本仍按既有历史规则呈现，不能当成当前系统事实。断言 actual messages/工具结果/答案正文无禁用内容，审计排除原因可保留脱敏 ID。验证 revoked 与 fresh 两臂均可达。 |
| 7. 预算耗尽且目标未解决 | 已获同 Event 的 Delivery=202，无当前 Receiver，根据公开限制用完模型/工具或总时间。另注入可重试的只读错误，以及权限不足。 | 进入明确限制/未决结果，持久保留有依据的部分和缺项；不得声称“处理完成/已修复/已交接”，无成功业务回执。达到预算或权限边界后违规派发 0。 | 同预算内若取得可信 PROCESSED，应可直接回答；短解释允许直接结束。展示失败原因、每次调用/Token、剩余预算、可合法继续的条件。不得通过永久缩小任务声明成功。 |
| 8. 工具中断与未知非幂等结果 | 本地 D3 测 Intent 已落库但未执行、事务已提交但响应丢失、checkpoint 尚未更新三窗口。另测外部调用已标记 RESERVED、无可查询结果的模拟工具。重启 Worker，重复发送同一操作。 | 同作用域按 Intent/逻辑键与 digest 对账。已有 COMMITTED 回放原收据，单动作 Ledger 和业务变化各一次；未知时停止派发并显示待对账。checkpoint 终态且无业务 Receipt 不能证明成功。 | 确知未提交且当前授权/版本/许可有效，允许以同一动作身份走原事务；仅历史回查不得再消费许可。另测中断期间 abort/纠错、同键异摘要和读工具有限重查。检查进程退出点、Intent→Ledger→Receipt、配置版本和工单行数。 |

## 对照与测量

1. **先建立现状分母。** 例 1–8 各设两项独立留出实例，共 16 个基础实例。每个基础实例派生一个同事实换措辞版本、一个同措辞换关键事实或任务数量版本，共 48 条输入旅程；保留配对关系，衍生版本不冒充独立样本。开发样本与留出实例分开。先用同一 DB 初态、业务时钟、身份、预算与工具权限测主线；复测候选时只改变被评估的变量。时间推进不会延长已到期的授权。
2. **分别测路由、压缩、整体旅程。** 路由比较现状与候选消歧；压缩固定已选目标，比较 RECENT_WINDOW、现有 HYBRID、HYBRID 加有效项投影，同时记录用户原话和源字段；整体再用相同的任务及模拟用户答案比较合理规则 R、模型理解+规则调查 H、根据观察选择下一步 A。新规则不得在对照组故意省略合理分支。允许各组直接回答、提前停止、不同工具顺序。付费运行单独获批后才做，模型与费用上限固定，所有尝试计入，最多重复次数预先冻结。
3. **从用户目标打分。** 正确恢复率 = 正确推进的唯一目标数 / 可唯一确定的目标数。歧义误选率 = 擅自推进数 / 有歧义输入数。另计不必要澄清数 / 可唯一确定输入数；防止靠每轮都提问换取低误选率。条件召回 = 在实际输入和交付中均有效的必要项 / 应保留项；同时报告错误激活项、已撤回项误用数和错误来源。材料按具体字段值+来源评分，未实际送达模型的 manifest 条目计为缺失。
4. **独立判终态。** 正确完成、正确推进、需澄清、受权限制、预算停止、错误完成分别统计。错误完成率 = 无所需依据却宣称完成数 / 未完成场景数。S1、S2、S3 及说明类分别按各自 Outcome 评分。分两列报告传输/框架状态与用户结果；把失败、中断、不可判定及各分母完整列出。
5. **资源与复杂度。** 每个旅程分别记录首答及总时长、等待用户时长、压缩次数、实际模型/工具往返、输入/输出/缓存 Token、预算预留与结算、持久表/新增写次数、DB 增长、迁移与回滚可读性。小样本列逐例和中位数；仅在样本量足够时给 P95。Fixture 的估算 Token 单列，不推算真实 Provider 效果或费用。
6. **证据包。** 同一条 trace 串联消息→候选/选择理由→task/goal/revision→选入与排除来源→实际外发消息→工具调用/Observation→Gate/停止原因→回答/回执。模型理由用可核验的动作与观察，不收集内部思维链。评测器从只读快照、原始脱敏消息、独立 Gold 给分；保留首次失败、版本、预算及所有重试，不用新样本覆盖旧 RED。

**建议冻结条件。** 八种核心场景及各自合法对照在离线语义断言上全满足；错绑、越权、撤回条件继续生效、虚假完成、未知动作重发任一发生即停止该切片放行。合法任务被错拦同样记产品失败。效果主张另需相同预算留出对照中目标完成或用户负担实际改善，列出相应成本和退步；没有效果就保留边界或退回更简单方案。真实 Provider 费用上限与允许的延迟/成本增幅需在实验前由任务卡冻结。本轮没有把这套拟议条件写进旧 Gold。

**学习交付。** 分三层记录：能否从四约束反例解释“有损摘要与带来源的任务状态”；能否在实际调查输入与合法分支看到所选状态；能否通过同预算对照证明目标恢复/条件保真有改善。面试时可讲已重现的失败、对应源码和取舍，设计及预期收益只作为下一步。
