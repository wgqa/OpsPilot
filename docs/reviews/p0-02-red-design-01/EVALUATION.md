# P0‑02 验收设计

**ACCEPTANCE_CANDIDATE · 待批准的评测设计。** 以 `93d5ac831447c5d23c677bd477958f9817ad8c2a` 和现有 RED 为比较基线。本页提出未来的验收分母与指标，既有 Gold、失败、Trace 保留原样。冻结前由主 Agent 核对样本、权限和结果门槛。当前阶段已执行记录见 [EVIDENCE](EVIDENCE.md)。

## 旅程与预期

条件槽位用稳定 ID 表示事件、协议版本、时间范围、报告格式。初始四项来自同 Task 四条独立的用户消息，保留序号和 digest。老会话分支单独记录一次有界候选提取与用户确认；新会话分支记录从创建/确认入口就具有结构化归属的输入。对照组用相同 TaskBinding、资源、模型配置、工具、输入预算、可信时钟和退出策略。简短合法查询仍允许直接回答或结束。

| 场景 | 必须具备的正例 | 必须挡住的反例或错误 |
|---|---|---|
| 四项同时生效 | 使用 20–40 轮同 Task 对话并跨过两次或更多压缩水位。最后明确“按之前四项继续”，当前块完整包含 E7、v2、10:00–11:00、分别报告 Receiver 和四条独立来源。输出报告也逐项评分。 | 第一个条件经摘要裁剪消失，错误地用第一条 CREATE_TASK 或最近一条 CORRECT 当成全部条件。E9 的专属原话和任何引用不得污染当前 Task。 |
| 只替换时段 | 正式确认全天后，当前块为 E7、v2、全天、分别报告。旧时段有替换关系和原始出处，可作为明确标注的历史解释。 | 旧时段继续生效、其它项意外被重置、两个时段同时作为约束。用同 operation_id 重放、异摘要冲突、过期版本的并发改动看是否原子拒绝。 |
| 撤销报告格式 | 正式撤回只将报告格式变为 REVOKED，仍引用旧历史记录；其它三项可继续。 | 取消后仍在有效块中、迟到摘要复活撤回项、误删最后一项以外的条件。 |
| 假设与未确认冲突 | “如果改成全天”仍保留旧时段。两条冲突提议并存时可先表达当前状态与不确定项，只在用户确认所指版本后应用。 | 将假设或普通、未确认的冲突文本自动转为已生效，或一律阻断仍可完成的合法解释。 |
| 选择与公共历史 | 同 Session 两 Task，使用正确 B ID，再交换 A/B 的活跃时间顺序。B 保留本 Task 的原始锚点、确认条件、来源合法的公共说明，模型能选择任意合法查询顺序。 | A 的条件、摘要、衍生答复或旧 checkpoint 进入 B；只有 NULL 标签而无可信原受理的材料不要推广为公共。 |
| 来源失效与撤权 | 在装配后、发送前、checkpoint 恢复和答案提交前，分别撤销 Task 或条件/材料依赖；源合法的邻近任务与无关公共内容仍可用。 | 指定材料、权限已失效的条件块或旧摘要全文重新出站；撤权竞态后依旧提交依赖该来源的有效结论。 |
| 有效条件整体超预算 | 测量扣除系统与必要工具成本后刚好能放下、刚好超出两臂。保留全局约束与尚未处理清单；允许每批可独立验证时有界分批或请求用户确认范围。输出明确缺项和下一步。 | 静默裁剪、摘要兜底冒称执行了所有条件、重复回放、放大窗口至无限。预算或源无法证明时不可默默以旧结果完成任务。 |
| 中断与恢复 | 对相同 revision 的干净只读 Run 恢复，重建有效块与引用；回收已持久化的幂等结果。确认变更后旧 checkpoint 重新核验，旧已确认条件仅留审计。 | 陈旧 Run 把已经撤回或跨 Task 的内容恢复为当前项，已派发结果未知时重发，或跳过 TaskControl/Intent/Ledger。 |

## 评分一览

1. **有效条件召回率**。每例在最终当前条件块中按实际生效的 ID、语义和最新修订逐项找回，除以预先冻结的有效条件数。无逐项状态的基线另报语义可恢复率。本次四条件保持有效的精确文本输入为 3/4；不把其它对照里的旧摘要文字当成“已激活”。
2. **已撤回条件错误激活数**。已撤销、已替换、未确认以及失效项按原因分组，分别计入实际当前条件块、模型执行意图和最终答复所采用次数。旧文本只在明确历史块出现可另记冲突暴露，只有把它当作有效项才计错误激活。审批和授权边界违反独立裁决，不能以均值抵消。
3. **条件来源对应正确率**。已发送的当前项中，当前 Task、来源消息 ID/digest、作用域与确认/生效修订同时匹配的条数除以出站项数。再列条件全集分母，区分引用错误与遗漏。本次 3/3 已送达引用正确，对全量为 3/4。
4. **实际出站覆盖率**。在 SDK 序列化的 `messages` 逐项判读，注明出现在有效条件块、摘要、原始 Task 锚点、最新正式纠错、近期原文或无来源自然语言。用相同内容交叉核对账本。只有摘要保留、manifest 写了 ID 或前代出现不等同于最终出站覆盖。
5. **结果满足率**。按有效条件单项核对输出与可信工具观察，另外报告全任务所有项均满足的比例、完成/部分/澄清/预算停止、误拒绝。纯 fixture ACK 和固定策略不得当作独立真实模型证据，本轮 NOT_RUN。
6. **资源与扰动**。记录压缩和回答分别的模型派发、输入/输出实际 Token 或本地估算、工具 Schema 开销、缓存、首答/总体延迟、DB 查询页数与实际行读数、SQLite 存储差值及索引成本。报告预算预留与失败，不推算出未经授权的 Provider 费用。用户确认轮数单列，避免隐性增加人机往返。

## 执行与冻结

- 同一冻结剧本先走基线 RED，再走候选，用相同 HYBRID 策略与观察。对历史长旅程用已授权的实验 profile 单列记录；同时保留默认 AUX 限制的安全终止用例。增加一个精简样本证明普通配额下也仍可执行合法短任务。
- 业务边界测试一律使用正常受理入口。mock 压缩能看到四项时全部返回一次，用于隔离持久化限额；另增压缩模型只返回三项、合并同类条件与遗漏引用的对照，证明有效条件能够独立恢复。旧材料、已撤权资料和另一个 Task 的配置不得以假想合成值拼进 Prompt。
- 冻结至少一组只换措辞的留出实例，以及一组只换受信事实、用户确认状态或资源权限的成对实例。先跑离线正式 API、Worker、stdio、SDK，再在额外明确授权后冻结模型和费用限额，真实调查的随机性和所有尝试完整留档。
- **候选门槛**。离线四项保真 4/4，出站当前项来源匹配全数，替换/撤销/未确认错误激活 0，越域或重复未知派发 0。仅读合法对照不得误拦。实际产品结果和资源预算阈值在正式实施卡与留出集冻结后独立裁决。若 A 的回放、确认或索引不能保证有界性能与精确失效，再评审 B 的增量 Schema 和回迁方案。
