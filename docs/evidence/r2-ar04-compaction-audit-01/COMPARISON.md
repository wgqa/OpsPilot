## Mechanism comparison

| Scheme | Trigger | Summary or selection method | Source data and recovery | Cost / OpsPilot fit |
|---|---|---|---|---|
| OpsPilot current `HYBRID` | Full candidate estimate exceeds `effective input budget` and eligible old history exists. | Model-generated source-cited JSON for an oldest contiguous prefix; keep the latest 12 eligible history rows. | Domain SQLite retains raw messages and dependency records; invalid summaries are excluded and raw history is rebuilt. | A summary model call only after the threshold; best current tradeoff for preserving durable audit sources, subject to the C06 failure below. |
| OpsPilot `RECENT_WINDOW` | Never invokes summary generation. | Select the recent 12-row window, then anchors/current input and required blocks. | Raw history remains in Domain SQLite, but excluded older context is not available to the answer unless separately reloaded. | No compression-model cost; intentionally loses old facts from the active prompt. |
| OpsPilot `ROLLING_SUMMARY` | Eligible history exists beyond the recent window, even if the prompt is under budget. | Same structured summary contract as `HYBRID`; later batches include the previous summary. | Summary dependencies and raw messages remain stored. | More compression calls and earlier lossy dependence; useful as a proactive comparison, not default evidence of better recall. |
| Codex local / remote | Auto compaction is requested by its turn/context-budget path; provider capabilities choose local or remote implementation. The selected `compact.rs` source is the compaction procedure, not the whole trigger rule. | Local path sends a summarization prompt and replaces active history with a compacted checkpoint plus retained context. It caps retained user-message history at 20,000 approximate tokens. Remote-v2 is provider-specific. | The live prompt is rewritten; session compaction metadata and replacement history are recorded. The selected code is not evidence that every discarded raw item remains queryable through the active prompt. | Local: summary inference; remote: provider-side operation. Useful concepts: explicit retained tail and trigger/implementation separation. Domain authorization and source dependency behavior would still need OpsPilot’s own controls. |
| Pi | `contextTokens > contextWindow - reserveTokens`; default reserve 16,384. Estimation uses provider usage where available and estimates trailing messages. | Walk backward to a valid cut point until `keepRecentTokens` (default 20,000), then summarize the prefix. If a cut bisects a turn, summarize its prefix separately and preserve its suffix. Iterative summaries update the previous summary; file reads/edits are also tracked. | A compaction entry points to the first retained entry; the append-only session path retains the journal and summary entry, while active context uses the checkpoint and tail. | One or two summary calls for a split turn, with possible extra file-operation bookkeeping. The token-based tail is a useful alternative to OpsPilot’s fixed row count. |
| OpenCode | Uses a model-window ceiling with reserve; defaults in the pinned source include a 16,000-token minimum reserve and 15% reserve share. Automatic compaction is due when estimate reaches the ceiling. | Model summary or provider-native compaction. It can precompute a background summary near the ceiling, hold it until needed, retain recent user messages, and shrink after an overflow response. | A checkpoint replaces the covered window in later prompts; native checkpoints are model-specific. The code retains session history and compaction metadata, but native replayability is provider/model dependent. | Background summaries can overlap the live turn and improve latency/cache use, but add speculative calls and stale-result invalidation complexity. |
| ZCode | Default window 200,000; preflight output reserve is capped at 21,000 and buffer is 13,000, giving default threshold 166,000. Requires enough history and stops after 3 consecutive failures. | `microcompact` first replaces older eligible tool-result content with a fixed marker, keeping the newest 5 groups by default; token-pressure threshold is the lower of 90% of the auto threshold and 2,000 tokens below it. It also has a 60-minute idle trigger and minimum-savings check. Full summary compaction remains a separate step. | Microcompact clones a request projection and returns replacement messages plus a boundary payload; the inspected function does not mutate the input array or itself delete durable Domain records. | Local clearing avoids a model summary call when enough old tool output can be removed; semantic detail is deliberately discarded from that prompt. Strong pattern for a separately measured, source-aware tool-output pruning experiment, not a substitute for keeping business evidence authoritative. |
| oh-my-pi Snapcompact | Chosen by ordered compaction maintenance after a token threshold, overflow, or incomplete-output recovery. Default method order starts with provider-native remote compaction, then `snapcompact`, `handoff`, `shake`, `soft`. | Deterministically serializes discarded history and encodes it into model-aware PNG frames; this replaces a summarization-model call for that method. `shake` is a different local path that uses recoverable artifact references. | The current branch records a compaction entry and image archive for model re-reading. This depends on vision support and image payload limits; it is not a text-verbatim guarantee. | No summarization call for Snapcompact, but image tokens still cost context and vision quality is model-dependent. Poor fit for OpsPilot’s exact identifiers, citations, and non-negotiable audit text. |
| LLMLingua | Invoked as a prompt-preprocessing step; no conversation-state trigger is specified by the paper. | Budget-controlled, coarse-to-fine token removal with iterative token scoring and language-model distribution alignment. | Produces a compressed prompt; the paper does not supply a durable conversation ledger or provenance/recovery protocol. | Targets prompt size and inference cost. A research baseline only; would need source-citation and no-fabrication tests before use on OpsPilot state. |
| LongLLMLingua | Same prompt-preprocessing framing, tuned to long-context tasks. | Question-aware compression and reordering to improve key-fact position and reduce long-context cost. | Not a durable history or retrieval mechanism; recovery requires the original input. | Useful for controlled long-context quality/cost experiments, not a replacement for Domain source-of-truth or summary invalidation. |

## Offline strategy comparison

The three measured configurations use the same fixture-seeding recipe; `RESULTS.json` records each case’s raw stored-message estimate, selected-message estimate, model input estimate, and exact sequence selection. `CONTEXT_BREAKDOWN.md` contains the block-level token breakdown. These are estimator counts from the local `cl100k_base` version, not provider billing numbers.

| Configuration | Measured case | Trigger and model calls | Selected history | Reading |
|---|---|---|---|---|
| A — `HYBRID` | `C03` | Effective budget was set one token below full candidate estimate; one summary call. | Oldest contiguous prefix summarized; recent rows retained. | Confirms strict `F > E` boundary. |
| B — `RECENT_WINDOW` | `C05` | No summary call. | Only 12 recent history rows selected. | Lowest summarization cost; early facts are absent from the active answer context. |
| C — `ROLLING_SUMMARY` | `C04` | One summary call even while below budget. | Oldest contiguous prefix summarized; recent rows retained. | Confirms proactive work and the same source-boundary policy. |

These cases compare mechanisms, not semantic answer quality. The current fixture does not prove that a model can accurately recover an early fact from a summary.

`C08` is a threshold demonstration, not a perfectly controlled schema-only A/B: the harness recalibrates `B` from 12,000 in `C08_BASE` to 10,839 in `C08` using the baseline `F + R + 10` recipe. The measured schema estimate rises from 1,214 to 2,709 tokens, while total reserved space rises from 5,203 to 6,709. Holding `B=12,000` fixed in the same measured formula would give `E=5,291`, still below `F=5,626`; this is a formula-based counterfactual, not a second measured run. The task's budget decrease is therefore supported, while the pair should not be described as isolating only one variable.

## Additional designs, not implemented

1. **Token-bounded recent tail.** Walk backward by measured message tokens and stop at a valid turn boundary while preserving task anchors and the current message. This avoids treating a 12-row window as a fixed-size token budget. The single oversized-message behavior needs its own fail-closed rule.
2. **Larger summary budget.** Raise the 512-token cap only if a live semantic evaluation shows that required identifiers, correction order, constraints, or unresolved status are being dropped. Measure additional output tokens and downstream prompt savings before choosing a new cap.
3. **Recoverable history retrieval.** Expose source-scoped read-only retrieval for raw messages or results already in the Domain ledger, with the same tenant/task/source validation and invalidation checks. This is a later experiment, not a new Memory platform.

No algorithm migration or production fix is implemented by this audit. C06 is recorded as `RED`: the `ROLLING_SUMMARY` trigger is true, but the initial `Loop.context()` preflight fails while building the first batch and the external run exposes only `WORKER_RUN_FAILED`. The minimal separate-review candidate is a typed error mapping at that preflight boundary in `opspilot/assistant.py`, preserving fail-closed behavior and zero provider calls. The risk is accidentally swallowing unrelated failures or continuing with partial user context; the handler must be narrowly scoped. See `RESULTS.json` and `ALGORITHM.md`.
