# Versioned Runner Design

`run_versioned_admission.py` is a small adapter around the already reviewed `run_remaining_live_gate.py` and its V2 Assistant/Domain harness. It dynamically loads the old runner without editing it, then pins the loaded module to this task's Base, Task ID, Review ID, accepted production Blobs, evidence directory and new Mock path. Runtime, Runtime Grant, frozen source validation, budget accounting and stop behavior continue to come from the existing code.

The adapter has no second authorization schema. The reused gate continues to require the exact manifest fields and checks the Task/Base, expiry, provider/model, case order, request/token limits, price snapshot, artifact pins and frozen source before dispatch. The new Task ID is `R2-AR04-LIVE-RETEST-GATE-01`; the separate review ID is `R2-AR04-LIVE-RETEST-VERSION-ADMISSION-01`. Historical task IDs and the review ID used as an authorization identity are rejected.

## Send path exercised offline

`Assistant Context Builder → PurposeCappedTransport → V2 frozen/model/request validation → BudgetedAsyncTransport authorization/budget checks → ledger slot and SEND_STARTED → httpx.MockTransport → response and Domain summary persistence → final prompt and Answer Manifest`.

The final Mock ledger has six slots and records `httpx.MockTransport` for every slot. Its trace has six `SEND_STARTED` and six `RESPONSE_RECEIVED` events in `MOCK` mode. This proves the requests reached the simulated transport after pre-send validation. It does not count as a Provider request or model-quality result.

The adapter's `live` method delegates to the same strict gate for a later separately authorized task, but this task did not invoke that method with a valid authorization. A negative test supplied only an old-task manifest; validation stopped before output creation or transport dispatch.
