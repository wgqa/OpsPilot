# M4-02 面试表达与追问

**90 秒项目表达：** 用户说“订单接口 200，但下游没回调”，不能直接理解成投递失败。我在原有受控 Agent 上增加一个独立的只读 S3 切片，让真实模型选择订单、投递、接收处理、知识检索和按需 Skill 等行动。事实经真实 MCP stdio 和本地 HTTP 取得，Domain Gate 核对归属、版本、时间、原始请求和事件关联。跨 Task 经验复用原 D5 审核/撤销机制，提示方法而不冒充当前证据。冻结 R/H/A 成对对照后保留所有失败；规则也能解决有限状态，因此不宣称模型准确率优势。价值是可观察的自主行动、事实纠错和可恢复的真实用户链路，安全来自可信程序。

1. **为什么 200 不能说明回调应该已经到达？** 查询成功与订单完成是两件事。PROCESSING 尚未到触发点；COMPLETED 才继续核对对应投递事件。202 也只是接收端入队确认，不能宣称处理完成。
2. **这是不是把 if/else 包装成 Agent？** R 明确是规则对照；Gate 的 if/else 是事实充分性判定。A 的合法下一步来自每次真实模型 Function Calling，可以检索知识、加载方法、读不同事实或提出澄清。要拿工具顺序和当时 Context 证明，不能只展示 Graph 图。
3. **模型到底决定了什么？** 在给定边界内选工具、查询词、方法 Skill 和简短理由；读到新事实后改变下一步，最后生成说明。tenant、资源、预算、证据资格、Outcome 和事务提交由程序控制。
4. **Knowledge 与 Skill 怎样区分？** Knowledge 是可检索的具体接口契约，带版本、来源、有效期和 digest；Skill 是可选调查方法。两个都不是权限，也不是当前业务 Evidence。工具 Schema 只提供有限目录，不预注入全部正文。
5. **为什么没用向量数据库？** 本轮只有两个受控短文档，有界词法检索足以验证真实检索与来源失效。大规模召回、排序评估和向量基础设施不属于本卡授权。
6. **Memory 为什么必须来源于别的 Task？** 这是跨任务经验复用的核心区别。来源 A 有真实诊断和 Evidence，经独立 APPROVER 启用；B 可在根因确定前获得方法提示，仍必须重新取当前事实。S3 只诊断，所以没有伪造 S1 Repair/Verification 字段。
7. **撤销后恢复会不会带回旧正文？** Checkpoint 保存引用；每次出站重新读取数据库和资产文件。跨进程实验先用过经验，再撤销/使知识过期，恢复同一 Run，核对后续实际请求与 Provenance。历史审计保留，不代表还能进入当前 Context。
8. **如何确认没有重复写业务？** S3 工具没有重发或修改能力，仍比较整个业务快照前后，并检查 Plan/Intent/Ledger/工单/Scope。审计和诊断落库不等于修改订单、权限或回调处理状态。
9. **模型返回多个工具调用怎么办？** 完整保留原响应，但一次只派发首个；其他请求标明未发送。下一轮必须重看新 Evidence 决定。所有实际 MCP 尝试计入原预算。
10. **模型不行动或重复查怎么办？** 没有有效调用、无进展或预算耗尽时有界停止，保存 INCONCLUSIVE；不抬高预算，也不把模型文字当成诊断。
11. **结果是否证明 LLM 更智能？** 只证明它实际参与调查选择与解释。R/H/A 在有限 Gold 上均可能正确；成本、无效调用和失败单独报告。资产进入 Context、动作发生变化、带来效果是三个不同结论。
12. **Demo 适用边界是什么？** 固定可信本地资源、单实例 Worker、SQLite 和本地 HTTP 接收端。没有外部回调平台、生产 IAM、自动重发或生产级故障覆盖，也未授权进入 M4-03 或其他阶段。

5 分钟核验路线：冻结计划和 Gold → R/H/A 原始 RESULT → A 的 Provider Prompt/tool reason 与对应 MCP Evidence → 资产恢复前后 Context → Web 截图和 HTTP/Run/回执关联。不要只背组件名。
