## 预算有余时，缩短锚点会引入事实丢失

同一测试将三条各不超过 100 字符的合成摘要分别送入真实校验、首次紧凑化和 `previous_summary` 再投影。每项源序列 3 均映射到确定的 Message ID，再投影回源序列。测试对照正文与来源，证据级别为确定性 L2。

|---|---|---|---:|
| `v4.2.7 to v4.3.1.` | 两处完整 | 时间线截到 `review f…` | 138 |
| `req-312 with req-731.` | 两处完整 | 正式更正截到 `mistyped Reque…` | 136 |
| `only when the receiver is not disabled.` | 两处完整 | 约束只剩 `Callback delivery is permitted for the replay r…` | 130 |

原候选的锚点长度分别为 72、72、48 字符，导致三个 HEAD 用例失败。三条输入分别只需 138、136、130 个本地估算 Token，源引用依旧有效。丢掉最后一个条件会留下看似允许的前缀，真实模型会如何解释仍待验证。完整输入、实际截断文本和退出码见 [EDGE_BEFORE_RUN.txt](EDGE_BEFORE_RUN.txt)。

补丁只在 `_compact_summary_document()` 的选择完成后，用剩余空间尝试恢复已选锚点的完整正文。仅恢复现有 100 字符限制内可完整容纳的条目，每次按完整 JSON 重新估算，超过 512 就保留带省略号的内容。原有选择顺序、来源和已选条目均保持。补丁加入后，三条完整正文均通过两次投影。见 [生产代码](../../../opspilot/domain/chat.py#L1395) 和 [回归日志](REGRESSION_WORKTREE_RUN.txt)。

| 发送边界 | Grant 的失效、撤销、共享预算不足和 UNKNOWN 回归验证原有控制。C06 覆盖超大用户消息的分类阻断、可解释通知、零模型发送，以及合法的超长 Assistant 摘要或最近窗口路径 | 历史 C06 RED 的内容与哈希均保留 |

`PARTIAL` 是该合成用例的证据判断。产品仍沿用同一摘要 Schema。每类条目上限、过长条目与预算竞争都可能丢事实。来源相同也无法证明两个条目的文本等价，当前同源条目候选选择仍依赖启发式。

六份冻结首轮 Provider 摘要用候选代码重放后，目标端点、Request ID 更正及版本/参数变化在两次应用投影后均可见。首次紧凑化为 499–509 个估算 Token。两个 Domain Fixture 还检查了实际组装的回答 Prompt。证据范围为 L2 可见性及调用路径，数值见 [RESULTS.json](RESULTS.json)。
