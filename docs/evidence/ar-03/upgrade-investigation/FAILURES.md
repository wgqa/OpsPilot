## 2. 认知与业务边界局限（非缺陷，为设计规范）

1. **协议比对不证明生产部署：**
   静态比对发现的协议差异（如 v2 的指数退避与 `attempt_count` 参数）仅代表规范演进，系统输出中始终包含 `deployment_version_verified: False`。严禁将文档差异当成集群线上已生效的证据。
2. **未绑定订单时的诚实拒答：**
   在未建立可信 `TaskBinding` 时，系统严禁为了迎合用户“看看客户是不是已经处理完成了”而编造订单状态。系统必须明确回答无法核查，并引导用户进行绑定。
3. **HTTP 202 不等于处理完成：**
   在回调协议中，传输层返回 HTTP 202 仅代表消息已被接收服务受理并进入队列（QUEUED），下游业务处理尚未完成。系统能准确辨析该状态，避免给出一线支持虚假的办结建议。
